Security & Information Storage

Deskripsi Vault

Vault WebToolsKita merupakan bagian khusus yang disiapkan untuk membantu menjaga informasi penting yang berkaitan dengan sistem administrator dan keamanan aplikasi.

Vault bukan tempat untuk membagikan informasi rahasia kepada pengguna umum.

1. Fungsi Vault

Vault dirancang sebagai area informasi keamanan yang dapat digunakan untuk mencatat struktur, aturan, dan informasi penting mengenai pengelolaan sistem.

  • Informasi keamanan sistem.
  • Dokumentasi konfigurasi penting.
  • Catatan pengelolaan administrator.
  • Informasi mengenai credential dan secret management.
  • Catatan prosedur keamanan.

2. Data Rahasia

Password administrator, Firebase private key, service account, API key, token, secret key, webhook secret, dan informasi autentikasi lainnya harus diperlakukan sebagai data rahasia.

Jangan menuliskan credential asli, private key, password, atau secret production pada halaman publik.

3. Service Account

File service account yang digunakan oleh backend harus disimpan secara aman dan tidak boleh dimasukkan ke repository publik atau frontend website.

Credential server harus tetap berada pada lingkungan backend yang terlindungi.

4. API Key dan Token

API key dan token yang digunakan untuk berkomunikasi dengan layanan eksternal harus dilindungi dari akses publik.

Jika sebuah credential diketahui pihak lain, credential tersebut sebaiknya segera direvoke atau diganti sesuai prosedur layanan yang digunakan.

5. Database

Database WebToolsKita berisi data sistem yang harus diperlakukan sebagai informasi internal.

  • Jangan membagikan database secara publik.
  • Jangan menghapus database tanpa backup.
  • Jangan menjalankan query yang tidak diketahui dampaknya.
  • Periksa backup sebelum melakukan perubahan besar.

6. Backend

Proses yang membutuhkan hak istimewa harus dilakukan melalui backend.

Frontend tidak boleh menjadi sumber otorisasi utama untuk operasi sensitif.

7. Administrator

Akses administrator harus selalu diverifikasi oleh sistem backend.

Informasi session pada browser tidak boleh dianggap sebagai bukti tunggal bahwa seseorang merupakan administrator.

8. Payment dan VIP

Data pembayaran, webhook, status transaksi, dan status VIP harus diverifikasi melalui sistem server.

Tombol pembayaran atau perubahan pada frontend tidak boleh digunakan untuk mengaktifkan VIP secara langsung.

9. CodeGuard

CodeGuard digunakan untuk membantu mendeteksi pola kode yang berpotensi membutuhkan perhatian keamanan.

Hasil pemeriksaan CodeGuard tetap harus ditinjau secara manual sebelum mengambil tindakan terhadap sebuah file atau sistem.

10. Prinsip Keamanan

  • Jangan membagikan credential.
  • Gunakan prinsip least privilege.
  • Backup sebelum perubahan besar.
  • Verifikasi akses melalui server.
  • Jangan menyimpan secret production pada frontend.
  • Periksa source code sebelum deployment.

11. Status Halaman

Halaman Vault ini merupakan halaman informasi read-only.

Isi deskripsi dapat diperbarui oleh developer secara langsung melalui source halaman apabila struktur sistem berubah.

Jangan menggunakan halaman ini sebagai tempat penyimpanan credential production secara langsung.
